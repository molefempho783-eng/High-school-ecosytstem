Technical design document · implementation-ready

White-Label High School Ecosystem Platform

.NET MAUI · ASP.NET Core 8 · EF Core / Azure SQL · Azure Blob Storage · Azure Managed Redis

Decision summary. Build one multi-tenant, API-first platform with a dynamically branded MAUI client. Azure SQL is the transactional system of record; Blob Storage holds media; Azure Managed Redis holds disposable cache and distributed locks. The requested Azure Cache for Redis role is retained, but Microsoft’s current guidance is to use Azure Managed Redis for new deployments.

2.1. Introduction

This document specifies a production-oriented, white-label platform for high schools. Each school is an isolated tenant identified by SchoolId; it controls display name, logo, colour tokens, domains, roles, public visibility, and data. The system spans academic delivery, campus-life operations, guest content, journalism, meetings, and gamification without exposing student data to visitors. Sections 2.2–2.10 describe scope, requirements, UI, API/layers, diagrams, schema, delivery plan, and references.

2.2. Application Overview

No Fixed Name and Placeholder Icon

The app shell ships as a neutral “School Portal” executable with a generic shield icon. At first launch it resolves the tenant from a claimed subdomain, QR/onboarding code, or selected school, fetches GET /api/v1/tenant/config, downloads the logo from Blob Storage, and applies primary/secondary/accent colours through a MAUI runtime ResourceDictionary. The tenant name replaces navigation titles, accessibility labels, splash text, and notification channel labels. Platform-store package names remain technical deployment identifiers; user-facing identity is tenant-controlled.

1 · Sports

Extracurricular & sports

Coaches manage teams, rosters, fixtures, attendance, venues and cancellations. A transactional availability service rejects a booking if a participant or venue overlaps an academic or extracurricular event.

2 · Guests

Visitor portal

Guests register using email verification and receive only public fixtures, approved articles and enquiry routes. Guest tokens carry Guest role and a public-content scope; no academic endpoints are returned.

3 · Newspaper

Integrated newsroom

Student journalists create rich-text drafts, upload moderated images, submit for editor approval, schedule publication and notify opted-in audiences after publishing.

4 · Meetings

Automated meeting scheduler

Parents see only teachers linked to their learner. They choose 15/30-minute slots from live availability; booking locks prevent races; the API returns an ICS calendar payload.

5 · Gamification

XP and badges

An immutable XP ledger records assignment, sport and reading events. A rules evaluator awards Bronze/Silver/Gold badges idempotently and publishes progress to the student dashboard.

Boundary

Privacy by design

Every query filters by SchoolId. Row-level filtering is enforced in EF Core global query filters and service authorization, with tenant ID derived from authenticated claims—not request JSON.

Azure hosting stack

Deploy the API to Azure App Service (Linux plan) with deployment slots; use Azure SQL Database with EF Core migrations and automated backups; place images/attachments in private Azure Blob containers behind SAS URLs; use Azure Managed Redis for tenant config/public-feed cache, rate-limit counters and short booking locks; use Azure Notification Hubs for push; Azure Key Vault + managed identities for secrets; Application Insights/Log Analytics for telemetry. Add Front Door/WAF when public traffic requires edge protection. Azure is preferred to Firebase because the .NET/API/SQL stack is native and relational transactions protect bookings and overlap checks. Azure for Students’ stated credit is easy to allocate to named Azure resources, while Firestore bills document/index operations and listener changes, creating workload-sensitive forecasting. See references [4]–[7].

2.7. Data Models and Schema Definitions

All entities include SchoolId:int and are scoped by a composite index beginning with SchoolId. IDs are Guid unless noted. Store time as DateTimeOffset; never rely on a device’s local time for conflict checks. List<int> JSON is used only where indicated; normalize relationships needed for joins.

2.9. Conclusion

The design makes tenant isolation, role boundaries, transactional scheduling and dynamic brand identity structural concerns rather than later additions. ASP.NET Core 8 and EF Core provide a maintainable service/domain boundary; Azure SQL protects relationships and concurrency; MAUI delivers a single branded client across the required device families. The 12-week plan ends with dedicated verification and stabilization, leaving the project structurally ready for immediate implementation.
